Stack

Pipecat — orchestration Sarvam — STT/TTS (Indic-friendly) OpenAI 4o — reasoning + tool calls

Activation routes

  • Side orb (always visible, every page) — tap to open voice panel.
  • Hero "Chat with my AI" CTA — same activation. The CTA is now voice-first; text mode is the fallback (caveman).

Auto-navigation behavior

  • Agent emits a structured tool call alongside its spoken response, e.g. scroll_to_section(id="indmoney").
  • Frontend reacts: smooth-scrolls to that section + adds a temporary 3px blue rail + soft glow (shown in C/D as the highlighted card).
  • Nav chip in the panel makes the navigation legible — "Now showing: Chapter 2 — INDMoney".
  • Sections need stable IDs in the DOM (already true for the landing: #my-story, #projects, #skill-map, #education). For sub-sections like INDMoney chapter, add per-chapter IDs.

Tool registry the agent will call

  • scroll_to_section(id) — navigate to landing section
  • open_project(slug) — focus a project card
  • set_volume(pct) / play_music(track?) / pause_music() — controls the music player from the previous mockup
  • open_chat(prefill?) — switch to caveman mode with optional prefilled question
  • end_call() — close the panel

Open questions before build

  • Latency budget — Pipecat + Sarvam + 4o can hit ~600-900ms end-to-end. Acceptable, but worth a target before we start.
  • Wake word? — or strictly tap-to-talk? Wake word is more magical but adds always-on mic permissions (deal-breaker for some).
  • Persisted state across pages — agent should survive a navigation (e.g., from / to /chat). Means mounting the panel in layout.tsx.
  • Caveman handoff — does flipping to text reuse the existing /chat backend, or run inside the panel? Wireframe D assumes in-panel; the alternative is full-page route.
