Skills Need Evals, Not Vibes

Via @sermakarevich — “How to write and test agent skills with evals”

Every agent skill should be scored on two axes, argues Sergii Makarevych’s new write-up: adherence — did the agent follow the skill — and effect — did it make things better. Two axes, because a skill the agent follows faithfully but that worsens outcomes is a different failure from a skill that would work if only the agent would use it. The diagnosis decides the treatment.

The method is properly scientific. Write measurable objectives for each skill. Define testable points, each paired with a hypothesis. Assign a grader to every point. Build eval arms that include a length-matched control — because a longer skill prompt can look better simply by being longer, and without the control you can’t separate the skill’s contribution from prompt-length effects. Run the evals, then decide whether to keep, cut, or drop each skill. Ship the skill text together with its testable points, evals and results. And re-run everything whenever the underlying model changes, because a skill tuned for one model is a hypothesis about another.

The skill eval matrix: score every skill on two axes
Adapted from Makarevych’s eval framework: the keep/cut/drop decision the evals exist to make.

The length-matched control is the quiet masterstroke. It admits that a skill is a prompt, and prompts have placebo effects: longer instructions can score higher just by nudging the model to try harder. Running the control separates real contribution from verbosity. It’s the same discipline as drug trials, applied to system prompts — and almost nobody in agent-building does it yet.

Main learnings

  • Two axes, four outcomes. Adherence without effect is harm; effect without adherence is a writing problem. Only measure both.
  • Control for length. A verbosity placebo inflates every un-controlled eval.
  • Hypotheses before skills. Each testable point gets a hypothesis and a grader — the skill ships with its evidence, not just its text.
  • Evals expire with models. New model, new run. A skill is a hypothesis about a specific model.
Practical takeaway — before writing another agent skill, write its two-axis scorecard and one length-matched control. The hour spent on the control is cheaper than the week spent wondering why the “better” prompt regressed.

One Memory, Every Agent

Via @mgonto — “The portable wiki”

Guillermo Rauch-adjacent builder Gonto published a technical write-up of a personal wiki that lives outside any single agent: Hermes, Grok Bot and Instinct all read the same memory. The organisation is disarmingly ordinary — CRM, Notes, Articles, Family — and that ordinariness is the point. The insight isn’t a cleverer embedding model; it’s memory as infrastructure, decoupled from whichever assistant you happen to be talking to.

The architecture has two lanes. A Nightly CRM ingestion lane pulls from Gmail, Slack, WhatsApp and calendar transcripts and builds the memory while you sleep; a separate task lane handles live requests, so context-building never competes with answering. Retrieval is a hybrid of SQLite FTS5 full-text search and OpenAI embeddings — exact match plus semantic, cheap plus smart. Both MCP and REST interfaces expose it, with per-client bearer credentials, so any agent can plug in without inheriting your whole identity.

The portable memory architecture: two lanes, one wiki
Source: Gonto’s write-up — the memory layer sits outside any single agent.

This is the unsexy infrastructure the agent economy quietly depends on. Models get smarter every quarter and forget everything between sessions; a durable, agent-agnostic memory layer is what makes them compound. Per-client bearer credentials are the security insight hiding in the architecture: share context, not identity. Read it alongside the lead story — if the answer box is the new front page, portable memory is the new cookie jar, and this is a sketch of who owns it: you do.

“One memory. Any agent.”— the portable wiki, via @mgonto

Main learnings

  • Memory should outlive the model. Decouple the wiki from the assistant; agents are interchangeable, memory isn’t.
  • Separate the lanes. Nightly ingestion and live tasks on different rails, so building context never slows answers.
  • Hybrid retrieval. FTS5 for exact, embeddings for semantic — cheap precision plus expensive recall.
  • Credentials per client. Any agent can read the wiki, but each gets scoped access, not your identity.
Practical takeaway — if you run agents daily, start a notes file outside every assistant and expose it via MCP. The agents change; the accumulation is the asset.

Start the Transformation in the Department

Via @vasuman (CEO, Varick) — “Where to Begin With AI Transformation”

Vasuman’s new article makes a claim most AI-transformation advice gets wrong: don’t start with a strategy deck or a pilot playground — start with discovery at the department level. That’s where the value is. Companies, he argues, sit in one of three states: not started, stuck at the copilot plateau, or stuck with pilots that never graduated. The ladder out is the same for all three, and it runs through the department, not the enterprise.

The seven steps: score departments on volume, cost and reach; agree KPIs up front; map the as-is process; design the to-be; build on existing systems rather than ripping them out; run in shadow mode before going live; and cultivate internal AI champions who carry it after the consultants leave. The worked example — a global distributor — lands the numbers: close times from twenty days to eight, AP exceptions from seven hundred a month to under fifty. Shadow mode is the underrated move: run the AI alongside the humans, compare outputs, and let the evidence — not the demo — earn the go-live.

Builder @giyu_codes liked the piece with a single line — “The best in the business. I kneel” — which is either sycophancy or a signal that practitioner-land is converging on this playbook. Read it against yesterday’s edition: ed25’s “seek friction” memo said go where AI commoditises least. Vasuman says the friction has an address — the department with the volume, the cost, and the exceptions.

The seven-step ladder, department-first
Source: Vasuman’s article — the department-level ladder out of pilot purgatory.

Main learnings

  • Discovery lives in departments. Enterprise AI value is found team by team, not in strategy decks.
  • Name the starting state. Not started, copilot plateau, or pilot purgatory — each needs the same ladder.
  • Shadow before live. Run alongside humans and let evidence, not demos, earn the rollout.
  • Champions over consultants. Transformation sticks when insiders carry it.
Practical takeaway — pick the department with the ugliest exceptions queue, score it on volume/cost/reach, and run steps one and two this week. If you can’t name the KPIs, you’re not ready for a pilot.

Read it next to the Alphabet story above: the stack owners print their moat; the stack renters borrow it, and the bond market is repricing the rent.

The Token-Budget Question

Via @paraschopra

Paras Chopra poses the question every serious project should be asking: “What durable thing gets compounded over time that’s hard to replicate by someone having an insanely large token budget?” Assume that if your project succeeds, it will get noticed — and assume the noter arrives with effectively infinite inference. What survives?

This is the moat question rewritten for the abundance age, and it’s sharper than the usual “what’s your moat” because it grants the attacker the strongest weapon upfront. Data moats erode when anyone can synthesise. Distribution moats hold longer. Proprietary workflows, embedded integrations, trust, regulatory position, and — the underrated one — the accumulated memory of a system that has run in production for years: these compound in ways tokens can’t buy. Read it as the strategic companion to today’s lead story: when the answer box decides, the durable asset is being the thing the answers are built on.

“What durable thing gets compounded over time that’s hard to replicate by someone having an insanely large token budget?”— @paraschopra

Main learnings

  • Grant the attacker infinite tokens. If your moat survives that assumption, it’s real.
  • Compounding beats caching. Production history, embedded workflows, trust — things that accrue, not things that compute.
Practical takeaway — write the one-sentence answer for your own project this week. If you can’t, the token budget is your competitor’s opening bid.

We Respectfully Decline

Via @spakhm — the essay, quoting @elonmusk

Elon Musk posted that next year he will give one of his SpaceX shares to every kid in America. Slava Akhmechet’s essay responds with an argument almost no one makes: express appropriate gratitude, then graciously reject the gift. He calls the gift a genuine act of altruism — and still the wrong thing to accept. Of America’s unique features, he writes, the most important is self-reliance: dignity derived from independence since the Republic’s first days. It is “unbecoming of American children to carry a mark of patronage from Trump accounts, Elon shares, Zuck dollars, or any other gifts from powerful benefactors, no matter how charitable.”

Strip the politics and there’s a clean mechanism underneath: gifts from the powerful create patronage relationships, and patronage quietly reprices independence. The essay’s move is to separate gratitude from acceptance — thank the altruism, decline the dependency. Whether or not the shares ever materialise, the argument travels: in an age of founder-philanthropists and platform largesse, the question isn’t whether the gift is generous. It’s what the recipient becomes by taking it.

Main learnings

  • Gratitude and acceptance are separable. You can honour the altruism and refuse the dependency.
  • Patronage reprices independence. Gifts from the powerful create relationships, not just transfers.
Practical takeaway — next time a platform offers you something free, ask what relationship it buys. Free is a pricing strategy; patronage is a position.

Work Like a Lion

Via @stijnnoorman — “Work Like a Lion. It’ll Change Your Life”

Stijn Noorman’s long-form piece introduces Lion Mode: Plan, Hunt, Rest. The lion is the model because it does nothing most of the day and then commits completely. Plan: goal-setting as dopamine engineering — aim at a star, reverse-engineer the path. Hunt: flow as the challenge-skill balance, attention designed rather than defended, activation energy lowered until starting is cheap. Rest: active recovery, not collapse. The canon runs from Naval to Seneca to Kobe, with Csikszentmihalyi and Kotler doing the heavy lifting on flow.

The mechanism worth stealing is the sprint-rest asymmetry. Knowledge work pretends to be a marathon and rewards looking busy for eight hours; the lion model says output comes from compressed, total effort followed by genuine recovery. It’s the human mirror of the quota wars above: even agents now work in shifts. Rest isn’t the absence of work in this framework — it’s the other half of the hunt.

Lion Mode: the three-beat cycle
Source: Noorman’s piece — the lion does nothing most of the day, then commits completely.

Main learnings

  • Sprint, don’t simmer. Compressed total effort beats eight hours of looking busy.
  • Rest is the other half. Recovery isn’t absence of work — it’s what makes the hunt repeatable.
  • Design attention, don’t defend it. Lower activation energy until starting is the easy option.
Practical takeaway — schedule one genuine hunt this week: a single total-commitment block, with the recovery booked in advance. The lion rests on purpose.

Rewiring Beliefs at Speed

Via @PromptLLM — Gemini 4 Argon on limiting beliefs

Asked for “an unconventional way to completely rewire limiting beliefs almost instantly,” Gemini’s Argon model answered with memory reconsolidation via a prediction-error jolt: recall the belief while simultaneously experiencing something that sharply contradicts it, and the brain’s update mechanism — the same one that cements trauma — rewrites the association. One paragraph, one mechanism, no journaling required.

Whether or not the neuroscience is airtight, the frame is useful: beliefs update on surprise, not on repetition. Affirmations fail because they confirm; the jolt works because it violates. It’s the same logic as the token-budget question above — grant the strongest counter-evidence and see what survives. The fastest way to change a mind, artificial or otherwise, is a clean contradiction, not a pep talk.

Main learnings

  • Beliefs update on surprise. Contradiction rewrites; repetition just rehearses.
  • Recall plus violation. Hold the belief and the counter-evidence at once — that’s the jolt.
Practical takeaway — pick one limiting belief and engineer a single clean contradiction this week. Don’t argue with it; ambush it.

Learn to Sell Like Yourself

Via @thedankoe — quoting @HussainIbarra

“The greatest mistake is being afraid of sales because you assume you have to sound like a sleazy salesman,” Dan Koe writes. “If you don’t learn to sell in a way that feels natural, you will get stuck working for a boss who sells in a way you probably despise.” The quoted piece — Hussain Ibarra’s “How to become dangerously good at selling” — supplies three strategies; the frame is the message: selling is a skill you customise to your voice, not a costume you put on.

It pairs with the ed25 through-line about choosing your friction. Sales is the friction most builders avoid — and the one that compounds fastest once it feels like you. The alternative Koe names is precise and a little brutal: someone else sells your labour in a way you’d hate. Refusing to learn sales doesn’t avoid salesmanship; it just outsources it to your boss.

Main learnings

  • Sell in your voice. The sleaze is a style choice, not a requirement.
  • Avoidance outsources. Not learning to sell means someone else sells you — their way.
Practical takeaway — write one offer in exactly your voice this week. No tactics, no script — just the thing, said like you.
